Overview

What is Picado Labs?

Picado Labs is an open-source ecosystem for building autonomous AI software agents that can be inspected, routed, executed, verified, and benchmarked.

Problem

Prompt-only agents drift.

Long chats lose context, model choice is often fixed, and success is too often accepted from the model's own claim.

Approach

Make the loop explicit.

Picado Labs separates planning, routing, execution, verification, and evaluation into focused tools.

Outcome

Proof before ship.

Agents must pass objective checks, run in bounded environments, and improve through benchmark feedback.

Architecture

Closed-loop AI engineering pipeline

The stack is designed as a feedback loop. Each stage produces a concrete artifact for the next stage: plan, selected model, code changes, verification results, and benchmark telemetry.

01 / Plan

build-with-ai

Repository • Issues

What is this? A zero-API CLI prompt architect. It helps a developer turn a software idea into ordered implementation phases, reusable decisions, and copy-ready prompts for any AI assistant.

How it works

It creates a local `.buildwithai/` workspace, stores project context, tracks completed phases, and injects past decisions into future prompts.

Best for

Project setup, architecture planning, reducing chat drift, and keeping AI-assisted development structured without API keys.

Developer goal
    |
    v
build-with-ai init
    |
    +--> project template
    +--> .buildwithai/context.json
    +--> .buildwithai/state.json
    |
    v
next prompt -> AI assistant -> developer records decisions -> next phase
npx build-with-ai init
npx build-with-ai next
npx build-with-ai done
npx build-with-ai export

02 / Route

Model Router

Repository • Issues

What is this? An explainable AI traffic controller that routes each task to the best local or cloud model using quality, cost, latency, capability, and reliability signals.

How it works

It extracts task features, removes models that cannot satisfy hard requirements, then uses Pareto scoring to select the best candidate in under 3ms.

Best for

Reducing model cost, using local Ollama when possible, routing hard reasoning tasks to stronger models, and auditing routing decisions.

Incoming prompt
    |
    v
Feature extraction: task type, complexity, context size
    |
    v
Hard filters: context window, tools, vision, coding, reasoning
    |
    v
Pareto scoring: quality + cost + latency + reliability
    |
    v
Selected model -> response + telemetry
python backend/app/cli/main.py doctor
python backend/app/cli/main.py route "Debug an async deadlock"
python backend/app/cli/main.py run "Write a token bucket limiter"

03 / Execute + Verify

Terminal Agent

Repository • Issues

What is this? A verify-first autonomous coding agent that edits files, runs commands, tests work, classifies failures, and can roll back checkpoints.

How it works

It observes the task and workspace, plans a bounded implementation, acts through typed tools, runs verification, then repairs or rolls back when checks fail.

Best for

Agentic coding tasks where success must be backed by tests, process limits, secret redaction, and repeatable recovery behavior.

Task + repository
    |
    v
Observe -> Plan -> Act with engineering tools
    |
    v
Run in LocalSandbox or DockerSandbox
    |
    v
IndependentVerifier executes tests
    |
    +--> pass: proof of done
    +--> fail: classify failure -> repair plan -> retry or rollback
pip install terminal-agent
terminal-agent run "Implement JWT middleware with unit tests"
terminal-agent status
terminal-agent rollback <checkpoint-id>

04 / Evaluate

AgentBench

Repository • Issues

What is this? A provider-agnostic benchmark platform for measuring coding agents on realistic Python and Node.js software-engineering tasks.

How it works

It runs agents against standardized tasks, validates output with tests, classifies failures, and calculates a 5D SWE score.

Best for

Comparing agents, calibrating model choices, evaluating PR-fix workflows, and building confidence before deployment.

Benchmark task
    |
    v
Clean sandbox -> agent under test -> code edits
    |
    v
Independent test suite
    |
    v
Score = correctness + pass rate + quality + efficiency + repair
    |
    v
Dashboard, telemetry, leaderboard, CI gate
python agentbench.py doctor
python agentbench.py init
python agentbench.py list
python agentbench.py run --benchmark fix-rate-limiter --provider ollama

Quickstart

Run the ecosystem path.

Start with the planning primitive, then add routing, execution, and evaluation as your workflow becomes more automated. 

# 1. Plan
npx build-with-ai init
npx build-with-ai next

# 2. Route
python backend/app/cli/main.py route "Build a secure token bucket rate limiter"

# 3. Execute + verify
terminal-agent run "Implement token bucket rate limiter with pytest tests"

# 4. Evaluate
python agentbench.py run --benchmark fix-rate-limiter --provider ollama
