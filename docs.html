Picado Labs Documentation

Technical guides, architecture specifications, CLI references, and SDK documentation for the Picado Labs open-source AI agent infrastructure suite.

1. Getting Started & Core Philosophy

Picado Labs is an open-source engineering lab building infrastructure for autonomous software-engineering agents.

LLMs alone generate hallucinated code and cannot run shell commands, execute unit tests, diagnose traceback errors, or measure their own correctness. Picado Labs solves this with three modular, local-first open-source systems:

  • 01 • Model Router: Evaluates prompt complexity and constraints to route requests to the best local (Ollama) or cloud model in <3ms.
  • 02 • Terminal Agent: Autonomous coding agent that executes tasks in a sandbox with test execution, 12-category auto-recovery, and atomic rollbacks.
  • 03 • AgentBench: Standardized evaluation suite that grades autonomous agents across 12 realistic software engineering benchmarks.
Core Philosophy: Route first for speed and cost efficiency, execute inside an isolated sandbox, verify independently with real tests, and benchmark continuously.

2. 5-Minute Quickstart

Install the complete Picado Labs toolchain via pip. All packages support Python 3.10+ and run natively with Ollama or any OpenAI/Anthropic/Gemini compatible provider.

Step 1: Install Packages

bash 
pip install ai-model-router terminal-agent agent-bench

Step 2: Start Local Inference (Optional, 100% Free)

For local-first operation without cloud API keys or costs:

bash 
ollama run qwen2.5-coder:1.5b

Step 3: Run an Autonomous Task

Dispatch Terminal Agent into any Git repository:

bash 
terminal-agent run "Fix expired token edge cases in auth/jwt.py" --provider ollama --model qwen2.5-coder:1.5b

3. Ecosystem Lifecycle

Every user request flows through a strict 3-stage lifecycle designed for high throughput, local privacy, and guaranteed test verification:

architecture flow 
[ Developer Task / Bug Report ]
              │
              ▼
   ┌───────────────────────┐
   │   01 MODEL ROUTER     │  < 3ms decision latency
   │  (Pareto Rule Engine) │  Routes to Ollama Local / Cloud
   └──────────┬────────────┘
              │ Selected Model + Prompt Constraints
              ▼
   ┌───────────────────────┐
   │   02 TERMINAL AGENT   │  Dual-sandbox (psutil / Docker)
   │  (Execute & Verify)   │  12-category recovery + atomic rollback
   └──────────┬────────────┘
              │ Execution Log + Git Diff + Artifacts
              ▼
   ┌───────────────────────┐
   │   03 AGENTBENCH       │  5D Composite SWE Formula
   │ (Evaluate SWE Metric) │  PassRate, Efficiency, Correctness
   └───────────────────────┘

4. Model Router Documentation

Model Router is a deterministic, sub-3ms LLM dispatch layer and real-time AI Traffic Control Room. It evaluates task complexity across 12 categories, checks hard constraints, and computes a Pareto multi-criteria score across Quality, Cost Efficiency, Speed, Capabilities, and Reliability.

Sub-3ms Pareto Routing Policies

Policy Optimization Target Default Dispatch Target
balanced Quality ≥ 0.85, Latency ≤ 1000ms, Cost ≤ $0.005 Local Ollama Qwen2.5 / DeepSeek R1
lowest_cost Zero cloud token cost ($0.00 / token) Ollama local / In-memory Mock
highest_quality Complex multi-file refactors & mathematical proofs Claude 3.5 Sonnet / GPT-4o
lowest_latency Interactive shell auto-completions (<500ms TTFT) Qwen2.5 1.5B Local

Explainability & Cost Guard

Every dispatch decision includes a deterministic trace explaining the rule match, token budget calculation, and confidence score:

json 
{
  "selected_model": "ollama/qwen2.5-coder:1.5b",
  "policy": "balanced",
  "decision_latency_ms": 1.42,
  "estimated_cost_usd": 0.000000,
  "explanation": "Task classified as CODING with MEDIUM complexity (0.45); matches local zero-cost Pareto tier."
}

Outage Fallback & Budgets

If a cloud provider returns a 429 rate limit or 503 outage, Model Router automatically cascades down to the local Ollama instance with zero interruption to the running agent. Spend thresholds trigger automated interventions (80% cost optimize, 95% local-only saver, 100% block).

5. Terminal Agent Documentation

Terminal Agent operates on a verify-first paradigm. Instead of trusting LLM self-reports, an independent verification engine executes tests and checks diff constraints before accepting work.

CLI Command Reference

Command Arguments Description
terminal-agent run <prompt> [--provider] [--model] Starts an autonomous engineering loop on the current repository.
terminal-agent resume [session_id] Resumes a previous paused or checkpointed session from SQLite state.
terminal-agent setup none Interactive wizard to configure Ollama, OpenAI, Claude, or Gemini.
terminal-agent doctor none Checks toolchains, process sandbox readiness, and provider health.
terminal-agent status none Shows active workspace session status and step count.
terminal-agent diff [--stat] Shows syntax-highlighted git diff generated by the agent.
terminal-agent test [--runner pytest|node] Executes the independent verification test suite.
terminal-agent checkpoint create | list Creates or lists atomic file snapshots before risky edits.
terminal-agent rollback <checkpoint_id> Reverts repository state to the specified safe checkpoint.
terminal-agent trace <session_id> Prints step execution trace, tool latency, and token metrics.
terminal-agent config [--init] Initializes or displays terminal-agent.config.yaml.

Process Isolation & Sandboxing

Terminal Agent provides dual-sandbox support:

  • Local Sandbox (psutil): Spawns isolated process trees with strict execution timeouts, process group kills, and non-blocking I/O monitoring to prevent runaway processes.
  • Docker Sandbox: Spawns an ephemeral container with strict CPU/memory limits and optional network isolation for untrusted code execution.

12-Category Auto-Recovery

When tests fail, Terminal Agent does not repeat the exact same prompt. Its FailureClassifier maps error stderr to 12 distinct recovery strategies:

  • SYNTAX_ERROR → Targeted AST repair at specified line offset.
  • TEST_FAILURE → Failing assertion extraction into prompt context.
  • DEPENDENCY_ERROR → Dependency inspection and module path resolution.
  • TIMEOUT → Loop complexity reduction & async timeout extension.
  • PERMISSION_ERROR → Sandboxed privilege escalation check.
  • NETWORK_ERROR → Offline fallback & mock network adapter.
  • CONTEXT_OVERFLOW → BM25 context pruning and token budget reduction.
  • TOOL_ERROR → Tool parameter revalidation and syntax correction.
  • WRONG_SOLUTION → Rollback to checkpoint and alternative plan generation.
  • COMMAND_FAILURE → Shell command argument correction and path validation.
  • INCOMPLETE_TASK → Missing contract criteria inspection and step resumption.
  • UNKNOWN → General traceback context injection and retry loop.

Independent Verifier

The verifier executes pre-flight tests, post-edit tests, and AST sanity checks. If assertions fail, it immediately triggers an atomic rollback to ensure your codebase is never left in a broken state.

5-Dimensional Composite SWE Score

Score (0-100) = 0.50 × Correctness + 0.25 × PassRate + 0.10 × Quality + 0.10 × Efficiency + 0.05 × Reliability

Running Benchmark Suites

bash 
python agentbench.py run -b fix-auth-jwt --provider ollama --model qwen2.5-coder:1.5b

GitHub PR Ingestion

Convert any public GitHub Pull Request into an automated benchmark task:

bash 
python agentbench.py ingest https://github.com/fastapi/fastapi/pull/1234 --category "Bug Fixing"

7. Security Architecture

Zero-Trust Command Policy

Terminal Agent inspects every shell command prior to execution using a 5-tier command classifier (SAFE, WRITE, DESTRUCTIVE, NETWORK, PRIVILEGED). Destructive commands (e.g. recursive deletions outside workspace, hard disk formatters, raw socket openers) are rejected instantly.

SecretGuard Redaction

All console logs, stdout/stderr streams, and git diffs pass through SecretGuard before storage or LLM context ingestion. Regex patterns automatically mask OpenAI keys, GitHub tokens, AWS credentials, and private SSH keys, and block reading files matching .env, *.pem, *.key, and .ssh/*.

8. Python SDK Reference

Model Router Integration

python 
from model_router.router.engine import RoutingEngine
from model_router.analyzer.heuristics import analyze_request

analysis = analyze_request("Debug distributed async queue deadlock in Celery")
engine = RoutingEngine()
decision = engine.route(
    prompt="Debug distributed async queue deadlock in Celery",
    policy="balanced",
    analysis=analysis
)
print("Dispatched to:", decision.selected_model.id)
print("Why this model?:", decision.explanation)

Terminal Agent Integration

python 
from terminal_agent.agent.loop import AgentLoop
from terminal_agent.config import TerminalAgentConfig
from terminal_agent.providers.ollama_provider import OllamaProvider

cfg = TerminalAgentConfig(
    provider="ollama",
    model="qwen2.5-coder:1.5b",
    sandbox="local",
    max_retries=3
)
loop = AgentLoop(config=cfg, provider=OllamaProvider(model=cfg.model))
session = loop.run("Fix JWT expiry leeway in src/auth/jwt.py")
if session.status == "VERIFIED":
    print("Task verified by IndependentVerifier!")

AgentBench Integration

python 
from agentbench.runner import BenchmarkRunner
from agentbench.ingest.github import ingest_github_pr

task = ingest_github_pr("https://github.com/fastapi/fastapi/pull/1234")
runner = BenchmarkRunner(provider="ollama", model="qwen2.5-coder:1.5b")
result = runner.execute(task.id)
print("AgentBench Score:", result.score, "/ 100")
print("Passed Tests:", result.passed_tests, "/", result.total_tests)
